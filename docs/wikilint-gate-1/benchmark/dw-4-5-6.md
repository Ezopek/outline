## DW-6 observation

The run did not overrun its deadline. It ended after about 30 seconds of the 60, when Sequelize's pool `acquire` timeout of 30000 ms (`server/storage/database.ts`) rejected the snapshot transaction's connection request. `readOnlyTransaction` passes that acquisition error through, so `lintWiki` returns the run-wide `VALIDATION_RUNTIME_FAILED`. DW-6 keeps that error a runtime failure. The amended criterion 9 accepts it as well as `VALIDATION_TIMEOUT`. After the holders released their connections, the pool reported 0 in use and 0 waiting (`heldPool.poolAfterRelease`). The harness waits up to 5 s for the pool to settle before it records that reading (DW-57, ledger `status: open`).

Timing never becomes a Finding, changes severity, skips a check or narrows scope. The held pool ended as a System Failure, not as a clean or partial result.
