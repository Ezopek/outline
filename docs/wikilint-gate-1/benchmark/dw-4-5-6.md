## DW-6 observation

The run did not overrun its deadline: it ended after about 30 seconds of the 60. It ended with the wrong System Failure, though. Sequelize's pool `acquire` timeout of 30000 ms (`server/storage/database.ts`) rejected the snapshot transaction's connection request before the `lint_wiki` deadline expired. `readOnlyTransaction` passes that acquisition error through. With the deadline not yet expired, `lintWiki` classifies it as `VALIDATION_RUNTIME_FAILED`.

At a test-scale deadline below 30 seconds, the same fixture ends as `VALIDATION_TIMEOUT` within the deadline (`harness.test.ts`). The outcome therefore depends on whether the pool `acquire` timeout or the request deadline fires first. Fixing the classification is outside this story. The observation is recorded here for the DW-6 decision.

Timing never becomes a Finding, changes severity, skips a check or narrows scope. The held pool ended as a System Failure, not as a clean or partial result.
