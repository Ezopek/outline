# Gate 1 evidence index

This index maps every binding requirement of the Wiki-linting increment to its Gate 1 evidence (Story 3.4, AC 1 and AC 4). The decision that follows from it is in [`decision-record.md`](decision-record.md). The collocated test [`gate1EvidenceIndex.test.ts`](../../server/wikiLint/benchmark/gate1EvidenceIndex.test.ts) checks that every inventory ID has exactly one row with no empty column, and that the decision follows the AC 2 rule.

Rules used for every row:

- **Source revision** is the commit the evidence was produced at: the accepted commit in a story spec's Coordinator Result (Stories 3.1 and 3.3), or otherwise the last commit of the retained file the row links.
- **Result** is one of `pass`, `fail`, `gap`, `unverified`, `contradictory` or `accepted-gap`. A claim with no retained raw output is `unverified`, never `pass`. No test run of the conformance suite is retained yet: Story 3.2, which produces it, is `backlog` in `sprint-status.yaml`. Every row backed only by collocated tests is therefore `unverified`. A Coordinator Result line such as `vitest: pass` is a claim, not retained raw output.
- A Story 3.2 deliverable (the conformance run and coverage map, the merge-base, the backport inventory, the generic-data review) is a `gap` whose closing source is Story 3.2.
- Story 3.3 evidence is a smoke run, labelled not Gate 1 evidence. Every row that needs the AD-17 reference run is a `gap`.
- `accepted-gap` is used only for a gap that the spine or the epic accepts by name, and links the accepting source.

This index is re-assembled after Story 3.2 and the Story 3.3 reference run. It produces no Story 3.2 evidence, changes no constant, and authorizes no image publication, deployment or rollout.
