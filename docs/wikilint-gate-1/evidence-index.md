# Gate 1 evidence index

This index maps every binding requirement of the Wiki-linting increment to its Gate 1 evidence (Story 3.4, AC 1 and AC 4). The decision that follows from it is in [`decision-record.md`](decision-record.md). The collocated test [`gate1EvidenceIndex.test.ts`](../../server/wikiLint/benchmark/gate1EvidenceIndex.test.ts) checks that every inventory ID has exactly one row with no empty column, and that the decision follows the AC 2 rule.

Rules used for every row:

- **Source revision** is the commit the evidence was produced at: the accepted commit in a story spec's Coordinator Result (Stories 3.1, 3.2 and 3.3), or otherwise the last commit of the retained file the row links. Story 3.2's accepted commit is `55fbe63b8c9960b292deeecf646e4e10e572dd8c` ([Coordinator Result](../../_bmad-output/implementation-artifacts/spec-3-2-close-layered-conformance-and-source-provenance-evidence-r2.md)). The AD-17 reference run was produced at the source commit its manifest records, `e5e16ec2588982ca674540100ae24186d1fc1081`. The three `ezopnas` runs were produced at `e1d81de21d30f199e424c512dbeddb9dd161f90c` ([test-wikilint-nas-runs.txt](raw/test-wikilint-nas-runs.txt)).
- **Result** is one of `pass`, `fail`, `gap`, `unverified`, `contradictory` or `accepted-gap`. A row is `pass` only when its linked evidence is a retained run, review or record. A claim with no retained raw output is `unverified`, never `pass`. A Coordinator Result line such as `vitest: pass` is a claim, not retained raw output.
- **Retained runs** are the Story 3.2 conformance runs recorded in [`conformance.md`](conformance.md) (Commands): runs 1–3 of `test:wikilint`, S1–S3 (shared supplementary) and V1–V3 (server supplementary), with their reports under [`raw/`](raw/test-wikilint-run-1.json). Every run passed, and per command the three runs have identical per-test names and statuses. A test row is `pass` when every test file it links passed in all three runs of its command. The requirement map is [`coverage.md`](coverage.md). After DW-58, three fresh-database `yarn test:wikilint` runs on `ezopnas` are retained as [`raw/test-wikilint-nas-run-{1,2,3}.json`](raw/test-wikilint-nas-run-1.json) with their log. Each passed 2291 tests and skipped 1, and the three are identical per test. Rows SM-I2 and the D-9 constant rows link them.
- A Story 3.2 deliverable (the conformance run and coverage map, the merge-base, the backport inventory, the generic-data review) links its Story 3.2 evidence file ([`conformance.md`](conformance.md), [`coverage.md`](coverage.md) or [`provenance.md`](provenance.md)) with the result that evidence supports.
- Story 3.3 evidence is the attested AD-17 reference manifest [`benchmark/reference-manifest.json`](benchmark/reference-manifest.json). It records `gate1Eligible: true`, no deviation and `derivation.gate1: ready`, and was run on the reference host that the operator accepted on 2026-10-25 ([`reference-attestation.txt`](benchmark/reference-attestation.txt)). [`constants.md`](benchmark/constants.md) and [`dw-4-5-6.md`](benchmark/dw-4-5-6.md) cite it. The smoke manifest [`benchmark/smoke-manifest.json`](benchmark/smoke-manifest.json) stays retained as earlier smoke evidence, not Gate 1 evidence.
- `accepted-gap` is used only for a gap that the spine or the epic accepts by name, and links the accepting source.
- Open deferred-work entries that bear on Gate 1 are noted in the rows they apply to, with their ledger status: DW-4 and DW-5 (`open`, rows DW-4 and DW-5), DW-57 (`open`, row DW-6) and DW-13 (`open`, row FR-7). DW-6 (`done`), and DW-50 and DW-58 (`done`, row SM-I2), are recorded too. The decision record lists the open entries that bear on Gate 1 but on no single row.

Story 3.4 assembled this index while Story 3.2 was `backlog`. It was re-assembled after Story 3.2 (DW-51), and again after the Story 3.3 reference run (DW-59), under the same rules. It changes no constant, and authorizes no image publication, deployment or rollout.
