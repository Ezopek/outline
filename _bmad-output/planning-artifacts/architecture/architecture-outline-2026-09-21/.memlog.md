- (decision) AD-4 [ADOPTED] — Findings use explicit text, document, relationship, or scope locations based on canonical Outline Markdown; protected target data is never part of a relationship location. - (decision) AD-5 [ADOPTED] — Policy is supplied through an optional WIKI_LINT_CONFIG_PATH pointing to one schemaVersion 1 JSON file. Binds configuration transport and lifecycle. Prevents environment-specific policy from entering reusable code and prevents multi-process live-reload drift. Absence means no Configured Collections; configuration is loaded once at startup and changes require controlled restart. Policies are keyed by collectionId and use activation read_only or enforced plus per-collection runtimeFailureMode closed or open, defaulting closed; MCP clients cannot set or override these fields.
- (decision) AD-5 [ADOPTED] — Configuration validation is two-phase. An unreadable file, malformed root JSON, unsupported root schema, duplicate or unidentifiable collection keys blocks startup because applicability cannot be established safely. With a valid envelope, each identifiable policy is validated independently; an invalid entry is retained as a fail-closed sentinel for that collection, produces a safe System Failure on reads, blocks MCP create/update, and does not affect valid or absent collections.
- (decision) AD-6 [ADOPTED] — Each policy has policySchemaVersion and policyFingerprint sha256:<lowercase hex> over canonical UTF-8 JSON containing schema version, activation, runtime failure mode, rule kinds, and parameters; object keys are sorted and array order preserved. Binds audit, response, and rollout correlation. Raw policy never enters responses, Event data, or logs. Invalid parseable entries expose only a safe hash, code, and diagnostic path. read_only activates lint tools without write enforcement; enforced activates MCP create/update validation. Rollout cannot complete until every serving instance reports the intended fingerprint.
