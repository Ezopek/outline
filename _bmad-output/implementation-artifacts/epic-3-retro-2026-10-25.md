### Aggregate views

- **AV-1 Architecture delta: one baseline production module changed.** `server/main.ts` replaces the inline `/_health` handler with the fork's `createHealthHandler` and reads `getPolicyReadiness()` at worker start (Story 3.1, AD-19). Other baseline changes are test infrastructure: `server/test/setup.ts` now takes a shared advisory hold for every server test file (DW-47), and `vitest.config.ts` gives the server project a 20 s test timeout (DW-58). No `wikiLint` import was added to other baseline modules. A dependency-graph tool was not run; the scope was narrowed to the import lines of the diff. *Disposition: accept.*
- **AV-2 Size growth: `server/wikiLint/benchmark/harness.ts` is 1,712 lines** (+1,720/−8 over the range) and `fixtureGenerator.ts` 1,234. The harness mixes seeding, case execution, statement attribution, budget evaluation, the held-pool re-run and manifest assembly in one module. It is benchmark-only code, but the lens findings below cluster in it. *Disposition: defer (A-4 and A-7 touch it; split it when it is next changed).*
- **AV-3 Spec-to-implementation: the write-eligibility rule is bounded by the fixture (verified).** Story 3.3 criterion 7 says each AD-13 write-eligibility constant "equals the largest value of its measure among retained enforced-write samples". The generator's largest Markdown size is `MARKDOWN_BYTES.max = 131072` (`server/wikiLint/benchmark/fixtureGenerator.ts:23-27`), and the link maximum is `MAX_LINK_REFERENCES_PER_DOCUMENT = 1000`. The derived constants therefore equal the fixture ceilings by construction, and DW-56 lowered `WRITE_ELIGIBLE_MARKDOWN_BYTES` from 262144 to 131072 (`server/wikiLint/application/writeDecision.ts:18`). Documents of 128–256 KiB in an `open` collection lost fail-open eligibility, and the rule can never find the constant too small. As-built matches the spec; whether the spec means what it now does is a product question. *Disposition: spec reconciliation (A-1).*
- **AV-4 Spec-to-implementation: constants cite a different run than the Gate 1 record (verified).** The doc comments of the four D-9 constants say they were fixed from "the AD-17 reference run of 2026-10-25 (source commit `7631d00b0`)" (`deadline.ts:10`, `lintWiki.ts:47-48`, `writeDecision.ts:15,24`). The retained Gate 1 manifest is the later run at `e5e16ec25` (`docs/wikilint-gate-1/benchmark/reference-manifest.json`), which confirmed the same values. *Disposition: fix (A-2).*
- **AV-5 Ledger drift.** `sprint-status.yaml` marks `dw-4-yield-between-lint-units` and `dw-20-bound-structure-read` `done`, while ledger entries DW-4 and DW-20 are still `status: open` (`deferred-work.md`). The Gate 1 index records DW-4 as `open` beside a `pass` row. DW-41 (story texts lack DW-20/DW-30) is open too. *Disposition: fix (A-12).*
- **AV-6 Pattern: verification the worker cannot run.** Five times in this epic a story's acceptance needed something the worker's sealed tool policy forbids, so the coordinator ran it and handed the output back through an inbox decision: the DW-47 two-process stress test, the Story 3.2 provenance `git rev-list --cherry-pick`, the DW-50 reset refusal paths, the DW-58 timeout probes, and the AC 7 build (spec decisions in `spec-dw-47-…`, `spec-3-2-…-r2`, `spec-dw-50-…`, `spec-dw-58-…`, `spec-dw-51-…`). Each cost a stop and a resume. *Disposition: process lesson (A-14).*

### Code lenses

- **CL-1 `enforcedImport`: an unavailable confirmation read counts as another delivery's row (verified; adversarial and edge-case agree).** `sameAsPersisted()` returns `false` when `readDocumentContent` returns `undefined` (`server/wikiLint/application/enforcedImport.ts:531-539`), and `onCommitted` then sets `probedOther = true` and writes no summary (`:780-783`). A transient read failure after a probe-established commit therefore leaves a committed document without its summary, and `committedFromSummary` cannot resolve it. Content equality also cannot tell a redelivery of the same intent from this attempt. This is the found-row attribution area of open DW-35/DW-36 (`spec-dw-35-dw-36-html-worker-found-row-attribution.md`, untracked). *Disposition: defer into DW-35/DW-36 (A-5).*
- **CL-2 `enforcedWrite`: the COMMIT timer can reach zero or below (verified).** `enforcement.commit(Math.floor(persistence.remainingMs()) - COMMIT_PROBE_BOUND_MS)` (`server/wikiLint/application/enforcedWrite.ts:654-656`) gives COMMIT no floor once P7 has used most of the persistence budget. A healthy COMMIT can "time out" immediately, and a probe that races it can report row 7 for a write that committed. *Disposition: fix (A-6).*
- **CL-3 Benchmark seeding has no disposable-database guard (verified).** `run.ts` is compiled into the production image. Seeding refuses only a seed it already seeded (`server/wikiLint/benchmark/harness.ts:538`), not a database that holds real teams. *Disposition: fix (A-7).*
- **CL-4 A partial full run is still Gate 1 eligible (adversarial and verification-gap agree).** `gate1Eligible` depends only on deviations and `smoke` (`harness.ts:1070-1071`, `referenceProfile.ts:391`). A full run with `--profiles wiki_150`, or with an injected held-pool deadline, stays eligible, and the `lint_wiki.wiki_1000.max` budget is then simply absent. `gate1EvidenceIndex.test.ts` treats NFR-1–4 as pass on `budgets.every(pass)`. The retained manifest has all 11 budgets, so the current decision is unaffected. *Disposition: fix (A-4).*
- **CL-5 The Gate 1 evidence is not tied to the constants in code (verification-gap).** No test compares the manifest's `constantsInForce` with the current constants, so changing a constant leaves the index test green and the record `ready`. This overlaps DW-60 (untested `contradictory` and `gap` branches). *Disposition: fix (A-3).*
- **CL-6 Readiness gates only `/_health` (adversarial and edge-case agree).** A worker that is not policy-ready keeps serving `/mcp`, including enforced writes; exclusion depends on an orchestrator honouring the health check (`server/main.ts:87-94`, `adapters/healthCheck.ts`). AD-19 binds readiness, so this may be intended, but the deployment precondition is not written down. *Disposition: open question for Gate 3 (A-9).*
- **CL-7 `/_health` readiness wiring has no test (verification-gap).** `createHealthHandler` and `getPolicyReadiness` are unit-tested, but nothing exercises the route that `start()` registers. *Disposition: fix (A-10).*
- **CL-8 Test mutex waits without bound (adversarial and edge-case agree).** `pg_advisory_lock` and `pg_advisory_lock_shared` have no `lock_timeout` (`server/test/databaseMutex.ts:54,130,154`), so a stalled exclusive section hangs the suite instead of failing it. The failure-path restore is untested (`databaseMutex.test.ts:136-170`). This overlaps DW-48 and DW-49. *Disposition: defer into DW-48/DW-49 (A-8).*
- **CL-9 Remaining lens reports, unverified.** These were not re-checked against HEAD and must not be acted on before triage:
  - `wikiReader.ts:373-399`: the DW-5 span starts after `findAll` materializes.

## Behavior verification

- **Exercised end to end:** the production build (`outline:wikilint-e5e16ec25`, `sha256:82a8ea72…`) ran the AD-17 harness in containers with PostgreSQL 14.2 and Redis, invoking `lint_document`, `lint_wiki` and enforced `create_document`/`update_document` writes through the registered MCP tools (in-memory transport). Every budget passed, the held-pool re-run ended inside the deadline with the pool idle after release, and the derivation reported every constant satisfying its rule (`docs/wikilint-gate-1/benchmark/reference-manifest.json`).
- **Suite determinism:** three fresh-database `yarn test:wikilint` runs on a second host (`ezopnas`, containers) at `e1d81de21` were identical per test (`docs/wikilint-gate-1/raw/test-wikilint-nas-run-{1,2,3}.json`).
