### Spec-to-implementation reconciliation and story boundaries

**F-1. An unavailable commit probe is treated as "absent". A committed HTML create can be reported as rejected, conflict, or aborted. Fix (blocking).**

- **Worker.** `finish` checks only `probeCommit(...) === "present"` (`server/wikiLint/application/enforcedImport.ts:517-531`), so an `unavailable` probe writes a non-committed summary, deletes the staged source, and returns rows 2/3/4/5. The first lookup also routes `unavailable` into `finish` with row 3 (`enforcedImport.ts:551-559`), and a second `unavailable` then reports row 3.
- **Requester.** An `unavailable` `probeImport` falls through to `switch (result?.kind)` and reports row 4/2/3 (`server/wikiLint/application/enforcedHtmlCreate.ts:309-339`).
- **Contract.** The spine's analogous rule is "row absent after a connection-level error, or a probe that cannot run, is row 7" (`ARCHITECTURE-SPINE.md:318`). Story 2.5's intent forbids "report a committed write as a failure" (`epics.md` Story 2.5 "So that"). AC4 does not define the unavailable branch.
- **Provenance.** Story 2.5's only completed follow-up review recorded four `[medium] [intent_gap]` findings on exactly this and ended `status: 'blocked'`. That review is in the archived stashed spec, under "2026-10-03 — Follow-up review pass".
- **Reviewer confirmation.** Three independent `bmad-review` findings confirm it: adversarial #1 and #2, and verification-gap #1, which found no test of `unavailable` in `finish`. The only probe-failure worker test fails just the first query (`enforcedImport.test.ts:1155-1183`).
- **Why blocking.** It is unresolved, untracked (no `deferred-work.md` entry mentions it), and the epic's own review gate stopped on it.

- **Recovery commit.** `ebc1e76d0` "Manual recovery after 2-5" deleted `spec-2-5-...md` (404 lines), changed `sprint-status.yaml` from `2-5-...: backlog` to `2-5-...: done`, and added only DW-10 to the ledger.
- **What was lost.** The dev spec already said `followup_review_recommended: true`: "The code added in this pass was not seen by an independent reviewer", namely the `deleteStagedSource` bound and the clock-skew caps (`git show f1f8aacec:...spec-2-5...md`, Auto Run Result). **F-3. An HTML worker row 6 established by the probe returns the attempt's own validation instead of `committedFromSummary`. Defer (spec reconciliation).**

- **As built.** On a rejected `commit()` whose probe finds the row, `runAttempt` returns row 6 with this attempt's `document`/`validation` (`server/wikiLint/application/enforcedWrite.ts:621-634`). The worker then writes its own committed summary (`enforcedImport.ts:737-751`).

- **Consequence.** With two deliveries of one invocation, the returned validation can describe a projection other than the persisted one. Source: adversarial #4.

### Diff-scope review (`bmad-review`)

**F-6. The COMMIT timeout consumes the probe reserve, so a commit timeout becomes row 7 without a usable probe. Fix.**

- **Mechanism.** `enforcement.commit(Math.floor(persistence.remainingMs()))` gives COMMIT the whole remaining persistence budget (`enforcedWrite.ts:618-620`). The probe bound is `Math.min(COMMIT_PROBE_BOUND_MS, remaining)` (`:621-624`), which is about 0 after a timeout. `boundedRead` refuses bounds below `SET_LOCAL_FLOOR_MS` (`server/wikiLint/adapters/writeTransaction.ts:440`) and returns `unavailable`.
- **Scope.** It affects the Markdown path (2.3) and the HTML worker (2.5).
- **Status.** Statically verified, not exercised at runtime. Source: adversarial #3.

**F-7. Staged blobs leak on three paths, through two divergent cleanup protocols. Fix (a, b); defer (c).**

- **(a) Requester source staging.** `within(FileStorage.store(...), ..., false)` abandons a slow upload, and the immediate `deleteStagedSource` can run before the object exists. Nothing deletes it when the upload lands (`enforcedHtmlCreate.ts:235-248`). `MediaStager` already handles this with `deleteLate` (`server/wikiLint/adapters/mediaStaging.ts:419-423`). The same problem was solved two ways across 2.5 and 2.6 (duplication map). Sources: adversarial #5, edge-case #3.
- **(b) Media validation failure.** When `Attachment.build(...).validate()` throws after `storeFromUrl` succeeded, the function returns `undefined` but leaves the key in `owned` (`mediaStaging.ts:407`, `438-446`). `media.cleanup()` runs only for rows 2-5 (`enforcedWrite.ts:461-463`), so the blob survives rows 6 and 7. Sources: adversarial #7, edge-case #4.
- **(c) Worker row 7 (`UnestablishedImportError`).** These paths leave the staged source in place (`enforcedImport.ts:521-524`, `552-555`). Retention may be deliberate, since a redelivery may need the source, but no owner ever deletes it later. This is coupled to the F-1 decision. Source: edge-case #1.

**F-8. The post-commit tail exceeds the reserve `admitPersist` holds. Defer to Story 3.3.**

- **Mechanism.** Admission reserves only persistence plus the audit bound (`enforcedImport.ts:726-731`). Case 6 then awaits callbacks, the summary, and `deleteSource()` (bounded at 1 s) before returning (`:744-751`).
- **Consequence.** A result that lands after `deadlineAt` sends the requester to `probeImport`. That path rebuilds a status-only validation and drops the Findings, or reports row 7.
- **Status.** Plausible; not exercised. Sources: adversarial #6, edge-case #7.

**F-9. The worker's deadlines are computed from epoch times taken on two hosts. Defer to Story 3.3.**

- **Mechanism.** `enforcedImport.ts:403-422` and `444-451` subtract requester-host and worker-host epoch timestamps, so skew moves queue-wait charging and `durationMs`.
- **Status.** The 2.5 dev spec says clock-skew caps were added in a pass that no independent reviewer saw (F-2). Sources: adversarial #11, edge-case #6.

**F-10. The worker does not re-check actor suspension or credential validity. Defer (Gate decision).**

`User.findByPk(..., { rejectOnEmpty: true })` and then `authorizeDocumentCreate` (`enforcedImport.ts:571-583`) never check `isSuspended`. The baseline `DocumentImportTask` behaves the same way, so this is baseline parity. AD-7's "reload the actor, re-authorize" may be read as requiring more. Source: adversarial #8.

**F-11. Accepted as specified or as baseline parity. Accept.**

- **Unpublish and metadata-only updates validate the whole projected document** (adversarial #9). This is mandated: `CLAUDE.md` says "Validate `update_document` against the fully projected post-edit document".
- **`job.finished()` race under `removeOnComplete: true`** (edge-case #5; `server/queues/queue.ts:41-42`). The baseline uses the same pattern at `server/queues/tasks/DocumentImportTask.ts:54` and `server/routes/api/attachments/attachments.ts:259`.

**F-12. Verification gaps at story boundaries. Fix (tests).**

- **(a) Row-2/4/5 `finish` conversions are untested.** Only the row-3 path is tested with a pre-allocated row that appears mid-attempt (`enforcedImport.test.ts:1323-1363`); rows 2, 4 and 5 are not. Source: verification-gap #2.
- **(b) HTML-with-media failure paths assert only `result.kind` or `isError`.** They never check the AD-20 row or the stored summary (`enforcedImport.test.ts:1839-1913`, `documents.enforcedMedia.test.ts:908-982`). The committed 2.5+2.6+2.7 path is covered (`documents.enforcedHtml.test.ts:393-434`). Source: verification-gap #3.
