### Diff-scope review (`bmad-review`: adversarial, edge-case-hunter, verification-gap)

**F-5. A requested collection that is revoked or deleted between lookup and snapshot yields a complete, clean result when its policy requires only `documents`. Disposition: fix.** Lenses: edge-case-hunter and verification-gap.
- Location: `server/wikiLint/adapters/wikiReader.ts:292-308`. For a collection scope the in-transaction `can(actor, "read", row)` is skipped (the check applies only to `configured_collections`), and `authorizeLintCollection` ran in a separate earlier transaction (`wikiReader.ts:80-94`). If the collection is revoked or deleted in between, `row` is null or unreadable, no documents are returned, and `lintWiki.ts:581-590` builds `complete: true`, `clean: true`, with the collection id and policy identity.
- The same window is already guarded for graph checks ("not vacuously": `lintWiki.test.ts:731`, `wikiReader.test.ts:1038`, `graph: { authorized: false }`). The `documents` check has no equivalent guard. Searched `wikiReader.test.ts` and `lintWiki.test.ts` for "no longer", "revok", "vanish", "deleted between": only the two graph tests match, so no test pins the documents-only case.
- Suggested guard: when `scope.kind === "collection"` and `!can(actor, "read", row)` inside the snapshot, fail with one generic System Failure (same shape as the graph case) and add a collection-scope test with `{ permission: null }` and a documents-only policy.
- Narrow window (milliseconds between two transactions), low probability, but the result is a false "clean".

**F-6. Failures that cannot be modeled leave no operator diagnostic. Disposition: defer (hardening, Epic 3).** Lens: adversarial.
- Locations: `server/tools/wikiLint.ts:120-122` and `:173-175` (`catch { return error(OPERATION_FAILED) }`), `server/wikiLint/application/lintWiki.ts:251-253` and `:379-381` (reader errors become `failed` or `VALIDATION_RUNTIME_FAILED`). `Logger` is used only in `readAudit.ts` and `policyConfig.ts`.
- A contract violation (`WikiLintContractError`), a SQL error or a parse bug reaches the agent as a generic code, and nothing correlates it for the operator. The contract does not require this diagnostic (the Spine requires diagnostics only for audit failure and startup), so this is an improvement, not a defect.
- Suggested guard: `Logger.warn` with `invocationId`, the operation, and the error class name only, never the message, location or content.

**F-7. The snapshot meters `documentStructure` after loading it. Disposition: defer (Story 3.3).** Lens: adversarial.
- Location: `wikiReader.ts:419-427`. `findAll` materializes the full `documentStructure` JSON of every graph collection before `meter.addStructureNodes` can fail it, so the AD-16 limit does not bound memory or parse cost for that read. Related to DW-5.

**Hypotheses checked and refuted (not findings, recorded so they are not raised again):**
- *Audit lost for `AuthenticationType.MCP` tokens.* `/mcp` allows `[MCP, OAUTH, API]` (`server/routes/mcp/index.ts:159-163`), but the authentication middleware never resolves to `MCP` (`grep` of `server/middlewares/authentication.ts`: no match), so `credentialAuthType` is always `oauth` or `api`.
- *`req.setTimeout(65000)` persisting on keep-alive sockets.* Measured with a Node http server: the third request on the same connection saw `timeoutBefore: 10000` again. Node reapplies `server.timeout` per request.
- *Webhook `*` subscribers receiving `wikiLint.*` Events.* `auditEvents.test.ts:152` ("never enqueues the Event") covers the raw `INSERT` path.
- *Unsanitized `toDOM` `href`/`src`.* Scanned every `toDOM` file in `shared/editor` that emits `href` or `src`: all route through `sanitizeUrl` or `sanitizeImageSrc`. The only non-sanitized `href` mention is `Heading.ts:154`, which reads `window.location`, not a user-controlled attribute.

The adversarial lens asks for at least ten findings. Only three survived verification. The remainder were already deferred (DW-1..DW-8), had been rejected with reasons in the story triage logs, or were refuted above, and I did not pad the list.
